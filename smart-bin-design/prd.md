# 全链路智能垃圾处理系统 · 产品设计方案（PRD v1.0）

**产品代号**：BinBot /「桶联」
**版本**：V1.0（概念验证阶段）
**日期**：2026-07-26
**角色**：产品经理（系统设计 × IoT 生态联动）

---

## 0. 一句话定义

> 一套由「智能垃圾桶主机」+「扫地机器人运输模块」+「家庭 IoT 中枢」组成的全自动垃圾处理系统：**检测装满 → 自动热封打包 → 喷雾除味清洁 → 自动套新袋 → 推出封口垃圾袋 → 召唤扫地机器人（升降护栏围护）运送至指定区域 → 全程无需人碰垃圾。**

---

## 1. 背景与痛点

| 现状环节 | 痛点 |
|---|---|
| 自动打包垃圾桶（如拓牛类） | 只解决"封袋+套袋"，封好的袋子仍需人拎走；桶腔长期残留异味，无自清洁 |
| 手动打包模式 | 装满与否靠人眼判断；想要远程/语音触发打包时，产品未接入米家等 IoT 平台 |
| 垃圾运送 | 家用机器人只能自动集尘，没有任何产品能把"一袋垃圾"从 A 点运到 B 点 |

**机会点**：把"打包垃圾桶"和"扫地机器人"这两个已普及的品类用 IoT 场景联动缝合起来，填补"最后一袋"的无人化空档。

---

## 2. 产品目标与边界

### 2.1 目标（V1.0）
1. 装满**自动检测**、自动封口打包（默认模式，无人值守）；
2. 封口后、套新袋前，**自动喷雾清洁除味**（解决长期使用异味）；
3. 手动/语音打包模式**必须接入米家 IoT**（小爱同学语音、米家 App、智能场景）；
4. 垃圾袋**自动推出桶体**，由扫地机器人（加装升降护栏套件）运送至用户指定区域（门口/阳台/厨房集中点）；
5. 全链路异常有降级方案（冗余设计，见 §9）。

### 2.2 明确不做（V1.0）
- 不做人形/机械臂抓取（成本高、安全认证难）；
- 机器人不做室外运送（HARR-E 类社区场景列为 V3 远期）；
- 不替代扫地功能——运输模块是现有扫地机器人的**加装套件 + 固件模式**，而非新机器人。

---

## 3. 用户与核心场景

**目标用户**：有扫地机器人 + 米家生态的城市家庭；对卫生敏感（有娃/有宠/懒人经济）。

| 场景 | 描述 |
|---|---|
| S1 日常全自动 | 桶装满 → 自动打包 → 清洁除味 → 套袋 → 推出 → 召唤机器人 → 运到玄关"垃圾暂存位" → App 推送"垃圾已就位，出门请带走" |
| S2 语音手动模式 | 用户对小爱说"打包厨房垃圾"→ 立即执行打包+运送全流程 |
| S3 定时/场景联动 | 每晚 22:00 若垃圾量 >60% 则打包运送；或"离家模式"触发清空所有桶 |
| S4 多桶多机 | 厨房桶 + 客厅桶 + 1 台机器人排队收运（机器人按优先级调度） |

## 4. 系统架构

```
┌────────────────────────────────────────────────────────────┐
│                     米家 IoT 中枢（云端+本地）               │
│   小爱语音 │ 米家App │ 智能场景引擎 │ 本地网关(断网可用)      │
└──────┬──────────────────────────────┬──────────────────────┘
       │ MQTT / MiOT spec             │
┌──────▼──────────────┐      ┌────────▼───────────────────────┐
│  A. 智能垃圾桶主机    │      │  B. 扫地机器人 + 运输套件        │
│  · 装满检测(ToF+称重) │      │  · 升降护栏环（围护垃圾袋）      │
│  · 热封打包机构      │      │  · 顶部载物平台 + 固定卡扣       │
│  · 除味喷雾模块      │      │  · "收运模式"固件（导航+召唤）   │
│  · 风吸套袋机构      │      │  · 到站卸袋提示                  │
│  · 底部举升+侧推机构 │      │                                │
└─────────────────────┘      └────────────────────────────────┘
```

**关键设计决策**：垃圾桶与机器人**不直接硬连接**，通过 IoT 中枢以"事件—场景"方式联动。好处：兼容用户已有扫地机（只买套件）、跨品牌可扩展、单点故障不拖垮全局。

## 5. 模块 A：智能垃圾桶主机（Bin）

### 5.1 装满检测与自动打包（默认模式）

- **双传感冗余**：
  - 顶部 **ToF 激光测距**：测垃圾堆高度，阈值默认 90%（App 可调 70–100%）；
  - 桶底**称重传感器**：≥ 额定重量（默认 3kg，按袋型自适应）触发；
  - **触发逻辑**：`高度 OR 重量` 任一达阈值 → 进入打包流程；两者矛盾时以 ToF 为准（防止一个哑铃骗过称重）。
- **热封打包**：无断点袋盒 + 封口杆交叉热熔切断（沿用成熟 ASAR 方案），封口时间 ≤ 12s，封口宽度 ≥ 8mm，承重 ≥ 5kg 不漏。

### 5.2 除味清洁喷雾（本次核心新增，解决"长期有味"）

- **时机**：封口完成、旧袋推出后、套新袋前（腔内无袋，是最佳清洁窗口）。
- **方案**：
  - 可替换**清洁液盒**（建议电解水/次氯酸类食品级消毒液，除味+抑菌，对宠物安全）；
  - 2 个微雾喷头：桶腔内壁 360° 环形喷雾 3 秒 + 封口机构喷杆自清洁 1 秒；
  - **UV-C 辅灯**（高配版）：喷雾后 30 秒紫外照射桶底排水槽；
  - 桶底设**导流槽 + 可拆洗接水盘**，残液不外溢，接水盘满则 App 提醒。
- **触发策略**：每次换袋必喷（默认）；可设"每 3 次一喷"省液模式；液量不足时 App+桶身灯双重提醒，**缺液不阻塞流程**（降级为干运行，见 §9）。

### 5.3 自动套新袋

- 沿用风吸铺袋：底部风机产生负压，新袋贴壁展开，≤ 8s；
- 检测：薄膜电流/红外确认袋已铺开，失败重试 2 次后报警。

### 5.4 垃圾袋推出机构（本次核心新增）

需求：封好口的袋子要从桶内送到桶外"交接位"，供机器人驮走。

```
┌──────────────────────────┐
│   顶盖+封口机构            │
│  ┌────────────────────┐  │
│  │   封口垃圾袋         │  │
│  │  ▓▓▓▓▓▓▓▓▓▓▓▓    │  │
│  └─────────▲──────────┘  │
│       举升托盘（剪叉/丝杆）│  ← 将袋子托举抬升
│  ════════侧推板═══════▶  │  ← 同步带推板，把袋子从
│      [交接滑门自动开启]    │     侧门推出至交接平台
└──────────────────────────┘
```

- **举升**：桶底托盘由静音丝杆/剪叉机构抬升，把袋子升离桶底、脱离负压区；
- **侧推**：桶身后部推板（同步带驱动）以 ≤0.1m/s 低速将袋子从**前侧自动滑门**推出，落在桶前的**交接平台**（离地 12cm，与机器人载物台同高对接）；
- **防倒**：滑门两侧有导向翼板，推出全程 ≤ 6s；
- **为什么用"推"不用"抓"**：机械臂抓取成本 ×5、故障率高；托盘+推板是纯线性机构，可靠且易做防水。

### 5.5 主控与连接
- Wi-Fi + 蓝牙 Mesh，完整接入**米家 MiOT spec**（见 §7）；
- 备用电池：停电可完成 1 次完整打包+推出（避免封一半的袋子卡住）；
- 桶身材质：抗菌 ABS，内腔圆角无死角设计，可水洗内桶。

## 6. 模块 B：扫地机器人运输套件（Bot-Kit）

### 6.1 形态：加装套件而非新机器人

| 部件 | 说明 |
|---|---|
| 载物平台 | 磁吸/卡扣固定在扫地机顶部，承重 6kg，表面防滑硅胶+3 点限位卡扣 |
| **升降护栏环** | 平台外圈环形护栏，待机时**降下收起**（不影响机器人钻沙发底、不增加碰撞），接到收运任务并装载后**升起 15cm**，围护垃圾袋防倾倒、防移位 |
| 交接引导 | 机器人尾部/前部设红外+UWB 对接信标，与垃圾桶交接平台自动对位（误差 ±2cm） |
| 固件"收运模式" | OTA 插件：新增"运送点"地图标注、低重心行驶策略（降速 40%、禁爬门槛>1cm） |

### 6.2 召唤功能（多入口冗余）

1. **IoT 自动召唤**：垃圾桶打包完成 → 中枢下发任务 → 机器人从当前位置/基站出发；
2. **语音召唤**："小爱同学，让扫地机来厨房收垃圾"；
3. **App/按键召唤**：米家 App 一键、桶身实体按键双击；
4. **定时召唤**：每日固定时间巡检各桶。

### 6.3 运送与到站

- 对位 → 桶推出袋子至机器人平台 → 重量传感器确认装载 → **护栏升起** → 低速行驶至用户预设"垃圾投放点"（玄关/阳台/后门口，App 地图上标注）；
- 到站：护栏降下，语音+App 提醒"垃圾已送达，请及时处理"；
- **交接逻辑可逆**：V1.0 到站后由人拎走最后一步；V2.0 预留"倾倒/推落"机构接口（可把袋子推入小区大垃圾桶方向预留）。

## 7. IoT 与语音联动（米家 MiOT）

| 能力 | 规格 |
|---|---|
| 设备接入 | 垃圾桶、机器人套件均以标准 MiOT 设备入网，支持本地网关（断外网场景可用） |
| 语音指令 | "打包垃圾""垃圾桶还剩多少袋""让扫地机收垃圾""垃圾送到阳台"（小爱同学意图库） |
| 手动打包强约束 | **若用户在 App 将打包模式设为"手动"，系统强制引导完成米家绑定**；未绑定则手动模式不可保存——确保手动=可语音/远程触发，杜绝"只能按桶身键"的假手动 |
| 自动化场景 | 官方场景模板：①离家模式→全屋打包收运 ②每晚 22 点垃圾量>60% 打包 ③打包完成→玄关灯闪烁提醒出门带走 |
| 状态开放 | 袋盒余量、清洁液余量、装载状态、运送进度全部上云可查 |

## 8. 核心流程状态机

```
[待机] ──装满检测/语音/定时触发──▶ [打包封口] ──▶ [腔内喷雾清洁]
                                              │
[完成/复位] ◀── [套新袋+铺袋检测] ◀── [UV照射(高配)] ◀┘
   ▲
   │         ┌──机器人忙?──排队/改派/降级人工提醒(§9)
[召唤机器人] ◀┘
   │ 对位成功
[举升+推出垃圾袋] ──▶ [护栏升起·装载确认] ──▶ [低速运送] ──▶ [到站卸袋提醒] ──▶ 回基站
```

## 9. 异常与场景冗余设计（重点）

| # | 异常场景 | 检测手段 | 降级/冗余方案 |
|---|---|---|---|
| R1 | 打包中途停电 | 备用电池 | 完成当前封口动作后安全停机；恢复供电后续推流程 |
| R2 | 袋子卡住/铺袋失败 | 电流+红外检测 | 重试 2 次 → App 报警+桶身红灯，桶进入"仅打包不套袋"人工处理态 |
| R3 | 清洁液耗尽 | 液位传感 | **不阻塞**：跳过喷雾继续流程，App 记录并提醒；连续干运行 5 次后强提醒 |
| R4 | 机器人正在扫地/充电/被困 | 中枢查询机器人状态 | ①任务排队（最长 30min）②家中有第二台则改派 ③超时→垃圾袋暂存交接平台+App 提醒人工取走，桶自动套新袋不影响继续使用 |
| R5 | 推出时袋体超重/超体积 | 称重+托盘压力 | 停止推出，回收至桶内，App 提示"垃圾过重请人工处理"，避免砸翻机器人 |
| R6 | 运送途中袋体倾倒/滑落 | 平台倾角+重量突变 | 立即停车、语音报警、拍照（带摄像头机型）推送给用户，原地等待处理 |
| R7 | 断网（Wi-Fi 挂） | 心跳检测 | 本地网关场景仍执行；纯离线时垃圾桶保持"装满自动打包+套袋"基础闭环，运送降级为桶身蜂鸣提醒人工 |
| R8 | 儿童/宠物靠近运行中机构 | 桶前红外+机器人碰撞传感 | 推出/护栏动作期间检测到人宠靠近即暂停，远离后续行；夹力限制符合家电安规 |
| R9 | 垃圾渗漏（汤汁类） | 桶底湿度传感 | 优先触发打包；渗漏量大致接水盘告警，建议"湿垃圾袋中袋"模式（自动套双层袋，袋盒支持双袋配置） |
| R10 | 机器人钻低矮家具场景 | 护栏升起状态+地图禁区 | **护栏升起期间自动更新机身高度禁行区**，禁止进入沙发/床底，防止卡住 |
| R11 | 多桶同时召唤 | 中枢调度 | 按"装满程度>先叫先得"排队，一次运一袋；高优先桶（厨房湿垃圾）可插队 |
| R12 | 指定投放点被堵（如门口堆了快递） | 机器人视觉/雷达 | 选备用投放点（App 可设主/备两个点），均不可用则返回交接位等待+提醒 |

| 指标 | 目标值 |

| 打包封口时长 | ≤ 12s |
| 全流程（检测→套袋→推出） | ≤ 60s |

## 12. 成功指标（北极星）

- 用户**每周人工触碰垃圾次数 ≤ 1**（仅剩出门顺手拎走）；
- 全流程成功率 ≥ 98%（异常降级不计失败，死机等人工干预计失败）；
- 异味投诉率：连续使用 3 个月桶腔异味反馈 < 2%；
- 套件兼容性：首发适配 ≥ 3 款主流米家系扫地机器人。

---

## 13. 风险与依赖

1. **米家生态准入**：需通过小米 IoT 开发者平台认证；若走不通，备选华为鸿蒙智联/自有 App+Matter；
2. **扫地机厂商配合**：载物套件涉及顶部结构与固件接口，优先与有开放协议的厂商联合定义；
3. **安规认证**：热封（高温件）、UV-C（泄露防护）、喷雾液（食品接触级）需 3C+相关检测；
4. **成本风险**：推出机构+双传感会推高 BOM，若售价敏感，V1.0 可将 UV 与称重传感列为高配选装。
