# 协作指南 ｜ 洲明品牌部汇报 PPT · 版本对照网站

> **协作平台**:Kimi 项目(把本对话转为项目,邀请同事加入)
> **正式环境(main 分支)**:https://shiwo233.github.io/share/unilumin-brand-report/
> **测试环境(staging 分支)**:Kimi 预览链接(每次更新后 AI 助手发到项目里)
> **网站仓库**:https://github.com/shiwo233/share(本站位于 `unilumin-brand-report/` 目录)

## 一、协作平台:Kimi 项目

1. 负责人在 Kimi 里把本对话「转为项目」(或新建项目,把对话与全部历史版本文件添加进去);
2. 在项目中邀请品牌部同事加入;
3. 同事在**项目对话**里直接发起更新(见下面两种方式),AI 助手在项目内处理,全过程留痕。

## 二、两种更新方式

### 方式一:下载 → 手动改 → 上传
1. 从项目里下载最新版 PPT(当前为 V9);
2. 自己手动修改(不改版式规范:字体 MiSans / 思源宋体,米白底、藏青字、赭橙点缀);
3. 把改好的文件上传到项目对话,AI 助手会:
   - 与上一版本逐页比对,生成**更改说明**(改了哪页、改了什么);
   - 如果版式跑偏(溢出、错位、字号不统一),**自动优化排版**后给你确认;
   - 生成新版本号(V10、V11……),旧版本全部保留。

### 方式二:直接打字描述
- 在项目对话里直接说:要改哪页、给数据或要求(例如「第 9 页表格加一行,XX 计划,已花 3 万」);
- AI 助手直接更新并生成新版本。

## 三、发布流程(测试先行)

```
发起更新(项目内) → AI 处理(比对/改版/出图) → 测试环境 staging(项目内通知全员)
      ↑________________ 成员评审 · 二次修改 ________________↓
                                            ↓ 确认无误
                              负责人批准 → 正式环境 main 同步发布
```

## 四、硬性约定

1. **版本永不覆盖**:每次改版另存新文件(V9、V10……),任何历史版本都能随时回看、回滚;
2. **数据口径一致**:预填数据页脚统一保留「数据为预填示例,正式汇报前请替换」,正式汇报前统一替换;
3. **每次改动必附说明**:AI 自动生成「改了哪页、改了什么」的更改说明,发在项目里;
4. **网站实时同步**:每次出新版,本站 PPT 浏览 / 架构演变 / 风格演变 / 版本浏览 / 拼版器全部同步更新。
